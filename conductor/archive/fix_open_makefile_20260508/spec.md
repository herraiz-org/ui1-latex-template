# Spec: Fix `open` Makefile Target to Depend on `pdf`

## Overview

The `open` target in the Makefile generated by `bin/new-activity` attempts to open the compiled PDF
using `xdg-open` without first ensuring the PDF exists. If the user runs `make open` on a fresh
activity directory, the command fails with a file-not-found error. Additionally, the root project
`Makefile` has no `open` target at all.

This track fixes both issues.

## Functional Requirements

1. **Generated activity `Makefile`** (written by `bin/new-activity`):
   - The `open` target MUST declare `pdf` as a prerequisite, so that `make open` always compiles
     the PDF before attempting to open it.
   - The `open` target MUST use `xdg-open` to open the resulting PDF.

2. **Root project `Makefile`**:
   - A new `open` target MUST be added, declared as `.PHONY`.
   - The `open` target MUST depend on `$(MAIN).pdf` so the PDF is always up-to-date before opening.
   - The `open` target MUST use `xdg-open` to open `$(MAIN).pdf`.

## Non-Functional Requirements

- No changes to the compilation logic, flags, or any other existing targets.
- Platform support: Linux only (`xdg-open`).

## Acceptance Criteria

1. In a freshly scaffolded activity directory, running `make open` compiles the PDF and then opens it.
2. In a directory where the PDF already exists, running `make open` recompiles and opens the PDF.
3. In the root project, running `make open` compiles `examples/plantilla.pdf` and opens it.
4. All existing `make pdf`, `make clean`, `make install`, `make uninstall` behaviours are unchanged.
5. BATS shell tests cover the generated `Makefile`'s `open` target dependency.

## Out of Scope

- Cross-platform support (macOS `open` command).
- Changes to the `clean` target or any other Makefile targets.
- Any changes to the `.tex` scaffold template or `referencias.bib`.
